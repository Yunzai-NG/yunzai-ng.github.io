# webui

面板本身。十一个页面、schema 驱动的配置表单、面板插件的宿主与商店。

## 它做什么

它是**唯一接管站点根路径**的插件 —— 内核只检测根路径有没有被接管，不自带兜底的前端。故
「面板由谁提供」只有一个答案，而替换面板不需要改内核。

十一个页面：概览、账号、日志、数据库、插件、扩展页面、插件市场、面板商店、配置、帮助、外观。其中三件
能力对写插件的人最有用：

- **配置表单自动生成。** 插件写完 `configSchema` 就有了表单，不必碰任何前端代码。
- **面板插件的宿主。** 别人的包放进 `plugins/` 即可往面板上加组件与页签。
- **面板商店。** 从索引装面板插件包；更新与删除在插件页。

## 怎么装

已有面板时，在**插件市场**里点更新即可，无须命令行 —— 市场会在插件目录内装依赖并跑
`build`（索引里声明了 `setup`），故下面那两步不必手动重复一遍。首次安装或面板打不开时从源码装：

```bash
cd <home>/plugins
git clone https://github.com/Yunzai-NG/webui-plugin.git webui
cd webui
pnpm install
pnpm run build
```

`<home>` 是内核主目录，即 `yzng init` 所在的那个目录。装完重启内核。

本仓库不发布至 npm，git 里也不含构建产物，故**两步都不能省**。少了 `pnpm install` 则没有
TypeScript 与 Vite；少了 `pnpm run build` 则 `dist/index.js` 不存在，内核找不到入口，插件被
跳过并记一条警告。`build` 同时跑 `tsc -b` 与 `vite build web`，只跑前者会得到一个能加载但整站
404 的插件。

构建之后 `node_modules/` 可以删掉：运行期只需要内核提供的 `@yunzai-ng/core` 与
`@yunzai-ng/types`，其余全是构建期依赖。

::: tip 在主目录之外克隆时
`tsc -b` 会因找不到 `@yunzai-ng/core` 而失败，先跑一次 `pnpm run link:framework`。
装在 `<home>/plugins/` 之下不需要这一步 —— 内核的 `init` / `start` 已把框架包链至
`<home>/node_modules/`，Node 与 tsc 都能自插件目录逐级向上找到它。
:::

## 用面板

访问内核日志里给出的地址（默认 `http://127.0.0.1:2536`），用同一行日志里的令牌登录。

| 页面 | 做什么 |
|---|---|
| 概览 | 运行状态、资源占用、近 24 小时消息、账号与近期告警；卡片可拖动改版面 |
| 账号 | 添加与登录机器人账号，改它们的适配器配置与重连策略 |
| 日志 | 实时日志，按级别多选筛选 |
| 数据库 | KV 与 SQLite 的用量、浏览与改删；需要内核 0.6.4 |
| 插件 | 已装插件的**全部管理**：配置、更新、重载、重装、装依赖并编译、卸载、删除目录 |
| 扩展页面 | 面板插件带来的整页，各自一个子项，见[扩展页面](../custom-page.md) |
| 插件市场 | **只负责浏览与安装**内核插件 |
| 面板商店 | **只负责浏览与安装**面板组件与主题 |
| 配置 | 编辑内核配置 |
| 帮助 | 命令一览与文档入口 |
| 外观 | 主题、明暗、版式、动效与备份五个页签，见[外观与主题](../themes.md) |

**装与管分在两页。** 市场只回答「有什么、装哪个」，装完给一条通往插件页的入口；已装插件的任何
后续动作都在插件页。分开的理由是同一个插件此前在两页各有一套按钮，而两页给出的事实并不一样 ——
市场那侧不知道插件此刻是否加载成功，却也摆着「卸载」。

插件页的卡片外只留三个常用动作（配置、更新、重载），其余收进「更多」：重装要把 `node_modules`
一并重下，装依赖并编译多半只在装坏过一次之后用得上。「更新」只在索引声明了更高版本时出现在卡片外，
否则留在「更多」里 —— 对一个已是最新的插件摆一个更新按钮，点下去只是换回同一个东西。
核心插件与面板插件卡片采用同一版式；配置弹窗也显示「可更新」和版本变化。面板包的更新与删除
只在插件页（商店页装好后只给「到插件页」），带 node 侧的包更新后须重载 webui 并刷新页面。商店说已装、
插件页却没有组件的包（只带主题的，或刚装还没刷新的）也各有一张卡片。页头的「检查更新」把两份索引一起回源。

**更新撞上本地改动时会多问一句**，且那一问不可关闭（10 秒倒计时，缺省暂存）。它卡在一个已经开始
的动作中途，此时按 Esc 不是「什么都没发生」而是让这次更新以一条错误收场。同一时刻只允许一个插件
处于管理流程中，因为这个问句是串行的。

插件页那几个动作按**安装目录名**请求，而列表里显示的是插件名（`definePlugin` 的 `name`，省了取 package.json）——
两者常常不同（某个插件的目录叫 `relay-checkin-plugin`，它自己声明 `relay-checkin`）。故删除确认框里
会写明「要删的目录是 `plugins/<目录名>`」：不可撤销的动作该报被删对象的名字。

**单文件插件**（`plugins/*.js` 与 `plugins/example/` 里的 js，见[单文件插件](../plugin-api.md#单文件插件)）
在版本旁标「单文件」，「更多」里只有查看、重载、卸载。更新、重装、装依赖、删除目录都按安装目录动手，
而它没有自己的目录 —— `plugins/example/` 里装着好几个，删那个目录会把它们一起带走。详情里给的是
文件路径。判据是内核 0.6.5 起才有的 `file` 字段，更早的内核上它们照旧显示成目录插件。

账号页的「配置」除适配器自己声明的那几栏外，最后另有一个**重连策略**页签（次数上限、首次间隔、间隔上限、
退避倍率），填了几项覆盖页签上就标几。四项各自可留空，留空即跟随全局配置，每项下方的灰字给出全局此刻的值。它们与上面那张
表单不是一类东西：那张由适配器的 `accountSchema` 驱动，而重连是内核替所有适配器统一做的事 ——
详见[按账号覆盖](../config.md#按账号覆盖)。只改备注或重连策略的保存**不会断开一个在线的号**，
故保存按钮的文案随内容而变：动过适配器配置才叫「保存并重连」。

概览页进入编辑态后卡片可拖动、缩放与移除，版面存在浏览器本地，换设备不会带过去。栅格横向 12 列、
纵向每行分两细格，卡片的边都落在格线上；磁盘、运行时、消息、账号与告警几格的高度随内容，只能改宽。
面板插件也可通过 `defaultLayout.fit` 使用自动高度。内容区不足 640px 时改为单列，侧栏展开不会把组件挤成窄条。
消息那一格读 `GET /plugin/webui/stats/brief`，该路由随插件注册，更新 webui 后要重载它一次才有。

操作成功的回执统一在页面顶部的提示条里：渐入渐出，至多三条同时在场、依次收起，停留时长按字数算，
鼠标悬停或键盘聚焦时暂停。错误仍留在页内的横幅里，不会自己消失。

**数据库页删 KV**：删一个键、删勾选的键（一次至多 50 个）之后，提示条上有约 8 秒的「撤销」，点了把删掉的键
连同过期时刻写回去（删之前已读回来留底）。一次超过 50 个、以及清空整个前缀不留底，后者要先键入那个前缀才能删。

页签条的选中块是滑过去的，不是跳过去的；关掉动效时直接到位。

面板与插件页的外链（插件主页、仓库、适配器登录步骤里的网址）只放行 http(s)：这些地址来自插件包与索引，
一条 `javascript:` 链接在面板的源里一点即执行，而访问令牌就在这个源里。打算把面板开到公网的，先读
[配置项 · 暴露到公网](../config.md#暴露到公网)。

只读模式（内核配置 `server.readonly`）下全部写操作被拒绝，面板会隐去相应按钮。

**主题**换的是一整身皮肤：配色、导航图标、卡片边框、开关贴图、插图与背景，面板插件的组件与扩展页面也跟着换。
内置「经典」（新装默认，也是兜底层）与「YUNZAI NG」，两款的配色都取自新的品牌图标：经典以云蓝、云青为主；
YUNZAI NG 的南瓜控件用黄橙红、背景与装饰用青蓝紫，导航图标、开关和插图一同换色。更多主题在面板商店的「主题」栏。明暗（跟随系统 / 浅色 / 深色）
与主题是两回事，侧栏底部那枚按钮切的是明暗。主题写坏把页面遮住时，地址后加 `?theme=safe` 打开。详见[外观与主题](../themes.md)，
自己做一款见[主题开发](../theme-dev.md)。

长页向下滚过一屏后右下角出现「回到顶部」，外圈是阅读进度；插件页页头下有一行计数（共几个、已加载、可更新、出错；可更新是核心插件与面板插件合计）。

**账号页**按适配器分页签，每枚只列该适配器的账号，地址里的 `?adapter=` 记着选的哪一枚。「添加账号」是个弹窗，
适配器就是当前页签那个：支持交互式登录的（声明了 `loginModes`）先给登录方式，手工填写收在下面，登录走到哪一步
有步骤条；登录中途关掉弹窗不会取消，会话留在页签下可以接着扫。适配器插件没加载的账号归进最后一枚
「未注册的适配器」，装回插件就会自动连上，不要了也能在那里删。

想自己往面板上加组件，见[面板插件](../panel-plugin.md)。

## 关键实现

**产物目录取自 `import.meta.dirname`，不取 `process.cwd()`。** 以服务或 pm2 方式启动时工作目录
并非插件目录。见 `src/index.ts`。

**面板插件只有一处落点**（本插件安装目录下的 `plugins/`）。曾有三路，收敛为一路的理由是：
三处落点意味着「我的组件为什么没出现」有三个要逐一排查的答案。

**目录只在 `setup()` 时挂一次，而清单端点每次请求都重扫。** 于是放进一个新文件后刷新页面即
生效；而 node 侧入口只在 `setup()` 时加载一次，那一半要重载 webui 才生效。这两种情形的下一步
动作不同，故安装结果里用 `hasServer` 分开告知。

**webui 自己的写路由要自行判定只读。** 内核的 `requireWritable()` 只拦 `/api` 之下的请求，管不到
本插件 scope 里的六条写路由（商店四条、面板插件配置两条），故经 `src/coreconfig.ts` 读内核配置的
`server.readonly` 自己拦。同一件事该是同一句话，故 403 的文案与内核那条一致。

**镜像前缀读内核的 `market.mirror`，不自己声明一份。** 国内网络下它是「能不能装上」的前提；
让使用者填两遍，第二遍必然有人忘，而忘的表现是「面板商店连不上，而插件市场是好的」。

## 源码在哪

[Yunzai-NG/webui-plugin](https://github.com/Yunzai-NG/webui-plugin)

| 路径 | 内容 |
|---|---|
| `src/index.ts` | 插件入口、面板挂载、清单与商店路由 |
| `src/panelscan.ts` | 扫描面板插件目录（只看磁盘，不执行 js） |
| `src/panelconfig.ts` | 面板插件包的配置：校验、存取、默认值 |
| `src/panelstore.ts` | 面板商店：索引、装 / 更 / 删 |
| `src/coreconfig.ts` | 读内核配置里的镜像前缀与只读开关 |
| `web/src/` | 前端（Vue 3 + Vite），`views/` 是那十个页面 |
| `web/src/panelapi.ts` | 注入给面板插件的 `api` |
| `web/src/panelcheck.ts` | 校验面板插件的形状，错时给出一句可示于界面的原因 |

# yenai-state

机器人状态图，移植自 [yenai-plugin](https://github.com/yeyang52/yenai-plugin) 的「椰奶状态 / 椰奶状态pro / 椰奶监控」三条命令。

## 它做什么

出一张状态大图：**每个账号一张卡片**、系统信息、CPU / 内存 / SWAP / GPU 资源环、磁盘占用、实时网速与累计流量、进程负载、fastfetch，以及 CPU / 内存 / 上下行网速 / 磁盘 IO 四条曲线。出图需渲染器（如 renderer-puppeteer），没装时**自动回退纯文本**，不会沉默。

## 怎么装

插件市场装完即用（`setup.scripts: ["build"]`，装依赖与编译由内核代跑）。

## 命令

| 命令 | 说明 |
|---|---|
| `#椰奶状态` | 输出状态大图 |
| `#椰奶状态pro` | 同上，另加默认只在 pro 里出现的板块 |
| `#椰奶监控` | 只输出四条曲线 |
| `#状态debug` | 回文本，列出各采集模块的耗时与内存 / CPU 增量 |

`pro` 与 `debug` 是同一 action 的开关，`#椰奶状态debug` 亦可。配置里 `defaultState` 开启后可省「椰奶」前缀写成 `#状态`（默认关，因为「状态」太常用，让位给别的插件）。

## 几处要点

- **默认为 `pro` 的板块只在 pro 里取数**（进程表、对外连通性测试），不是藏起来 —— 这两项耗时明显，非 pro 时根本不采，状态图因此快几百毫秒。
- **一个账号一张卡**，顺序按内核给出的账号顺序，说话的号排最前；整机数据在账号卡之外**只画一遍**。卡上的适配器名是该账号实际在用的那一个，不是已装适配器列表。
- **监控曲线要有数据才画**：数据来自后台采样任务（`monitor.open`，默认开，间隔默认 60s），刚启动时曲线为空，等一分钟即可。曲线默认存 KV，重启不丢。
- **取不到的数据不当 0**：采集层区分「这版没这个键」与「值确实是 0」，前者不显示，后者才显示 0 —— 免得一个恒 0 的 CPU 环被读成「机器闲着」。

## 配置

首次加载在 `config/yenai-state.yaml` 生成，字段名与源插件 `state.yaml` 对齐，便于迁移。唯一对不上的一处是 `psTestSites.list`：本插件用**一行一项的字符串数组**（`名称 | 网址 | 走代理`，竖线分隔），而非源插件的对象数组 —— 因为面板的字段组件渲染不了对象数组。升级后旧的对象数组会被丢弃、退回默认，需按新写法重填。
